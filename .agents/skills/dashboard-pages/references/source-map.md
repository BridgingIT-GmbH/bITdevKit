Shared consistency components live in `src/Presentation.Web/Dashboard/Pages/`: `ControlStyles`, `FilterActions`, `RefreshControls`, `ListFooter`, `FilterStateScript`, `GrowingListScript`, `ModalActions` and `ModalScript`. Their typed models live in the parent Dashboard directory. Messaging and Operations illustrate explicit applied filters; Jobs and the brokers illustrate routed Diagnostics and continuation; storage editors illustrate dirty-dialog preservation. `FilterActions` renders text Apply and a circled-X Reset with an accessible name. `ListFooter` keeps Load more, Rows per load and the cumulative loaded count below items; Documents, Blobs, Permalinks and Entities illustrate the footer placement.

Workload throughput uses `DashboardMetricsHistory`, `DashboardWorkloadChartsModel` and `Pages/WorkloadCharts.cshtml` in the shared Dashboard directory. Jobs/Messaging/Queueing supply exact aggregate instrument definitions; typed metric copies are excluded from chart history. Runtime capture is process-local and independent of viewers.

Orchestrations Diagnostics uses the shared workload charts and collector. Instance start/finish/outcome/duration measurements are emitted by `InMemoryOrchestrationExecutor`; activity attempt/return/exception/duration measurements use `MetricsOrchestrationBehavior`. Activity returns include nonterminal outcomes and are not unique completed instances.

System separates Overview, Process, Environment and Diagnostics routes. `DashboardSystemHistory` samples existing runtime and HTTP snapshot services once per second into bounded history; `SystemDiagnostics.cshtml` renders it through `WorkloadCharts`. HTTP rates use counter deltas over actual elapsed time, and latency means divide completed-request latency by completed requests. Missing sources and idle timings stay null.

Orchestration definition metadata is read by `OrchestrationDefinitionReader` and rendered by `Definitions.cshtml`. Use the existing `IOrchestrationDiagramService` for flow diagrams through the dashboard group, independently of optional management endpoints. Keep definitions visible if metadata or a diagram fails; never execute activities or transition conditions while projecting metadata.

Orchestrations Instances uses `ListFooter` and `createGrowingLists`, with composite creation-time/instance-ID continuation through `IOrchestrationQueryService.SearchAsync`. Keep the row selector below the items and preserve the applied scope for appends.

The Orchestrations Instances selector reads registered runtime names through `OrchestrationDefinitionReader.GetNames`, without building definitions or running activities. Its `name` query parameter matches exactly and is retained across paging and navigation.

MCP separates Overview, Connections, Handlers and Operations using `McpDashboardEndpoints` and `Pages/McpViewNavigation.cshtml`. Each route refreshes only its selected content. Keep the schema modal outside refreshed content and pause refresh while it is open.
