# Introduction

![Status: In progress](https://img.shields.io/badge/status-In%20progress-yellow)

This plan implements the Entities dashboard page defined in [spec-presentation-dashboard-entities.md](../docs/specs/spec-presentation-dashboard-entities.md). The page is a rough table editor for every `IEntity` type reachable through a registered `IGenericRepository<T>` or an ActiveEntity registration. It searches with `FilterModel`, loads rows incrementally ("Load more"), masks configured properties on the server, and offers create, clone, update (with diff), delete and bulk delete only to principals that satisfy a global `EditPolicy` or `EditRoles` gate. The page appears automatically when at least one entity source exists and can be disabled with `DashboardEndpointsOptions.DisabledPageKeys.Add("entities")`.

The plan can be read without the conversation that produced the spec. File paths and symbol names are authoritative; line numbers are hints and may move. Where the plan and the spec disagree, the spec wins and the plan must be corrected.

- **REQ-003**: Picking an entity type shows a table with `Id` first, scalar columns, value-object JSON previews and read-only audit columns, filled with the first batch and a "Load more" button when the batch is full (AC 3). **Tasks:** `TASK-019`, `TASK-026`, `TASK-047`, `TASK-048`
- **REQ-004**: The filter toolbar builds a `FilterModel` (property, type-aware operator, typed value, AND/OR match mode, quick search over string properties) and mirrors it in query parameters (AC 4). **Tasks:** `TASK-026`, `TASK-049`, `TASK-053`
- **REQ-005**: Unknown properties, unsupported operators or unparsable values return an inline error and never an unhandled exception (AC 5). **Tasks:** `TASK-026`, `TASK-049`
- **REQ-006**: Principals that do not satisfy `EditPolicy`/`EditRoles` see no edit toggle and no write controls, and every write endpoint returns 403 for them. With neither setting configured the page is permanently read-only (AC 6). **Tasks:** `TASK-008`, `TASK-036`, `TASK-041`, `TASK-050`
- **REQ-007**: Editors in edit mode can create, update and delete; repository and ActiveEntity behaviors (validation, auditing, domain events) run on each save (AC 7). **Tasks:** `TASK-025`, `TASK-029`, `TASK-030`, `TASK-041`, `TASK-051`

- **REQ-009**: Invalid JSON for a value-object or collection property is rejected before reaching the repository (AC 9). **Tasks:** `TASK-027`, `TASK-030`

- **REQ-020**: "Clone" (edit mode) opens the create modal prefilled without `Id`, `ConcurrencyVersion`, audit state, masked and hidden values (AC 20). **Tasks:** `TASK-051`
- **REQ-021**: A URL carrying entity key, filter, sort and selected `Id` restores the state and opens the detail panel; missing rows show "not found"; edit state is never in the URL (AC 21). **Tasks:** `TASK-042`, `TASK-053`

- **REQ-025**: When the Change History page is enabled and tracks the entity type, the detail panel links to `{changeHistoryPath}?registration={key}&entityId={id}`; otherwise no link renders (AC 25). **Tasks:** `TASK-023`, `TASK-035`, `TASK-050`, `TASK-058`, `TASK-059`, `TASK-060`
- **REQ-026**: Write requests need no antiforgery token: editors succeed without one and non-editors get 403 (AC 26). **Tasks:** `TASK-036`, `TASK-041`
- **REQ-027**: A masked value-object member keeps its stored value when the value object is saved through the JSON editor without replacing the member (AC 27). **Tasks:** `TASK-028`, `TASK-030`
- **REQ-028**: ActiveEntity types are recorded automatically in a Domain `ActiveEntityRegistry` by the `ActiveEntityConfigurator<TEntity, TId>` constructor, so both `AddActiveEntity(...)` paths fill it without extra developer code (spec Entity Discovery). **Tasks:** `TASK-001`, `TASK-002`, `TASK-003`, `TASK-004`
- **REQ-029**: Repository types are discovered from closed `IGenericRepository<T>` registrations (T : `IEntity`) in the service collection, including manual registrations (spec Entity Discovery). **Tasks:** `TASK-013`, `TASK-016`
- **REQ-030**: Documentation covers setup, enablement, disabling, access model, masking and reference builders, reflection opt-in risk, export and security, with fictional models only (spec Documentation). **Tasks:** `TASK-073`, `TASK-074`, `TASK-075`
- **SEC-001**: Edit is deny-by-default. The server evaluates `EditPolicy` (through `IAuthorizationService.AuthorizeAsync`) or `EditRoles` (through `ClaimsPrincipal.IsInRole`) on every write. UI hiding is never the only protection.
- **SEC-002**: No antiforgery. The dashboard is a backend admin surface. Write endpoints (create, update, delete, bulk delete) follow the existing dashboard POST convention (`.DisableAntiforgery()`, JSON bodies) and are protected by host dashboard authorization plus the SEC-001 edit check. `IAntiforgery` is neither registered nor used.
- **SEC-003**: Masking is applied on the server before serialization. Masked values never reach the browser in any representation.
- **SEC-004**: Client-supplied property names, operators, sort fields and entity keys are resolved only against discovered `EntityPropertyDescriptor`/source instances, never by arbitrary reflection lookup.
- **SEC-005**: Batch size (`MaxBatchSize`), export rows (`MaxExportRows`), bulk selection (`MaxBulkSelection`), JSON request body size (256 KiB) and filter condition count (20) are bounded on the server.
- **SEC-006**: Server values are HTML encoded by Razor; client-rendered text uses `textContent`. No `innerHTML` with entity data.
- **SEC-007**: Logs use `[EntitiesDashboard]` templates with entity type, id, operation, user name and row counts only. Property values are never logged.
- **SEC-008**: CSV cells starting with `=`, `+`, `-` or `@` are prefixed with `'` to prevent spreadsheet formula injection.
- **CON-001**: The feature lives in `src\Presentation.Web\Entities\Dashboard` (namespace `BridgingIT.DevKit.Presentation.Web.Entities.Dashboard`) and has no EF Core dependency. Only the Change History link provider lives in `Presentation.Web.EntityFramework`.
- **CON-002**: Repository access uses only `GenericReadOnlyRepositoryResultExtensions` (`FindOneResultAsync`, `FindAllResultAsync(FilterModel, ...)`) and `GenericRepositoryResultExtensions` (`InsertResultAsync`, `UpdateResultAsync`, `DeleteResultAsync`). ActiveEntity access uses the static `FindOneAsync(object id, ...)`, `FindAllAsync(FilterModel, ...)`, `InsertAsync(TEntity, ...)`, instance `UpdateAsync(...)` and static `DeleteAsync(object id, ...)` `Result` overloads.
- **CON-003**: No `DbContext` access, no hard delete, no wrapping transaction for bulk delete, no total count query (`FindAllResultPagedAsync` and `FindAllPagedAsync` are not used).
- **CON-004**: Entity data is never cached. Only type metadata (sources, descriptors, compiled delegates) is cached in a singleton catalog built lazily on first use.
- **CON-005**: Domain gains only `ActiveEntityRegistry` and `ActiveEntityDescriptor`; Domain has no dashboard dependency.
- **CON-006**: No new NuGet packages. Authorization and System.Text.Json come from the ASP.NET Core shared framework.
- **GUD-001**: Follow `.editorconfig`: file-scoped namespaces, `this.` for members, no underscore prefixes, one blank line between public members, `var` when obvious.
- **GUD-002**: Every public type and member gets XML documentation with a `<example><code>` usage example (AGENTS.md).
- **GUD-003**: Documentation uses fictional models (`Customer`, `Order`, `Region`) and never names repository example applications.
- **GUD-004**: Run `dotnet build` and `dotnet test` sequentially, never in parallel, in this worktree.
- **PAT-001**: RazorSlice pages with `_ViewImports.cshtml`, shared `_DashboardLayout`, `MapDashboardPage<TSlice>(...)`, as in `src\Presentation.Web\Profiling\Dashboard\DashboardEndpoints.cs` and `src\Presentation.Web.Auditing\Dashboard\Pages\*`.
- **PAT-002**: Map-time gating as in `src\Presentation.Web.Auditing\Dashboard\DashboardEndpoints.cs:22` (`options is not { Enabled: true } || ... || options.DisabledPageKeys.Contains("auditing")` → return).
- **PAT-003**: Page and card construction as in `src\Presentation.Web\Profiling\Dashboard\DashboardPageProvider.cs` (`new DashboardPage(...) { Group, GroupOrder, Order, Description, RememberedViews, Card }`, card try/catch with `Unavailable`/`Error` fallbacks).
- **PAT-004**: Load more as in `src\Presentation.Web.Auditing\Dashboard\Pages\LoadMore.cshtml`; detail dialog as in `Pages\Detail.cshtml`/`DetailDialog.cshtml` there.

## 3. Alternatives

- **ALT-001**: Numbered paging with total counts (`FindAllResultPagedAsync`). Rejected: the workflow is to narrow with filters; the count query is extra cost; other dashboards use "Load more".
- **ALT-002**: Explicit antiforgery token validation on writes. Rejected: the dashboard is a backend admin surface behind host authorization; registering `IAntiforgery` would also make .NET 8+ add antiforgery middleware to the whole host.
- **ALT-003**: Discover entities through EF Core `DbContext` models. Rejected: adds an EF dependency, misses non-EF repositories and ActiveEntity providers, and bypasses repository behaviors.
- **ALT-004**: Per-entity edit policies. Rejected for v1: one global gate keeps the access model simple (spec Access Model).
- **ALT-005**: A Domain `RepositoryRegistry` filled by `RepositoryBuilderContext`. Rejected: misses manually registered `IGenericRepository<T>` services; the service-collection snapshot covers both.
- **ALT-006**: Record ActiveEntity types in `ActiveEntityConfigurationBuilder.For<>()` and `ActiveEntityBuilder.Build()`. Rejected: `Build()` is optional; the shared `ActiveEntityConfigurator<TEntity, TId>` constructor covers both paths.
- **ALT-007**: A separate `Presentation.Web.Entities` package. Rejected: the feature needs only Domain abstractions already referenced by `Presentation.Web`, like Logging and Profiling.
- **ALT-008**: Client-side masking. Rejected: values would leave the server (SEC-003).

## 7. Risks & Assumptions

- **RISK-001**: Reflection writes with `AllowNonPublicSetters()` bypass domain invariants in setters and factories. Mitigation: per-entity opt-in, documented warning, repository/ActiveEntity behaviors and validation still run.
- **RISK-002**: Some providers may fail to translate `OrderBy` on owned `AuditState` members. Mitigation: catch the failed `Result`/exception, fall back to `Id` ordering and show an inline notice; covered by an integration check when a provider test exists.
- **RISK-003**: Without antiforgery, a logged-in editor visiting a malicious site could be targeted by cross-site requests. Mitigation: JSON bodies (`application/json` is not a CORS-simple content type, so browsers preflight cross-origin POSTs), edit mode is opt-in per principal, and the guide recommends host authorization for the dashboard.
- **RISK-004**: `EntitiesDashboardServiceCatalog` keeps a reference to the `IServiceCollection` after the container is built. Mitigation: read-only use, scanned once lazily; documented in code comments.
- **RISK-005**: Several `IGenericRepository<T>` registrations for the same `T` resolve last-registration-wins; the dashboard shows that one only. Mitigation: documented in the spec and guide.
- **RISK-006**: A missed masking configuration exposes sensitive data in View mode. Mitigation: documentation recommends dashboard authorization and explicit masking; masking is server-side only.
- **RISK-007**: Scrutor decoration replaces inner registrations with `DecoratedType` service types; detection by closed `IGenericRepository<T>` service type may change with Scrutor versions. Mitigation: unit test with a decorated repository (TEST-004).
- **RISK-008**: Typed id types without `Create(primitive)` or a single-parameter constructor cannot be parsed. Mitigation: those types are view-only for id-based actions and the UI explains why.
- **ASSUMPTION-001**: When `AddEntitiesDashboard()` is not called, default `EntitiesDashboardOptions` (read-only) are acceptable and the page still appears when sources exist.
- **ASSUMPTION-002**: The Change History registration `Key` format and the `registration`/`entityId` query parameters stay stable.
- **ASSUMPTION-003**: The ActiveEntity in-memory provider works in TestServer tests once the global service provider is set with `app.UseActiveEntity(app.Services)` or `ActiveEntityConfigurator.SetGlobalServiceProvider(...)`.
- **ASSUMPTION-004**: Antiforgery is out of scope (owner decision 2026-11-02): the dashboard is a backend admin surface protected by host authorization.
- **ASSUMPTION-005**: `Presentation.UnitTests` can see internal Presentation.Web types (existing `InternalsVisibleTo`, as used by `DashboardFeatureIcons` tests).
