# Introduction

![Status: Completed](https://img.shields.io/badge/status-Completed-green)

Implement the accepted [Storage Dimensions specification](../docs/specs/spec-storage-dimensions.md) and [ADR-0044](../docs/adr/0044-independent-storage-dimensions.md). Add explicitly supplied Dimensions beside existing descriptive Properties. Blob Storage and Document Storage retain separate implementations. SQL Server, PostgreSQL, and SQLite are the initial EF targets; every other provider rejects Dimensions before I/O.

Baseline: commit `246a9b683`, following the `main` merge at `cce9527aa`. The Properties alignment prerequisite and ETag conditional updates already exist. This plan implements Dimensions, not another Properties refactor. Its first release gate proves the annotated schema, exact search representations, and unsupported-engine behavior before enabling the public feature.

Implemented and accepted; finalization completed on 2026-11-20. Independent EF Dimensions, all adapters, dashboard queries and consumer adoption are complete. The original 22-case server qualification is retained alongside two full current-model million-owner combined runs. PostgreSQL passed every strict gate. SQL Server was accepted with the exact release exceptions below; raw failed results remain failed.

## 1. Requirements & Constraints

- **REQ-001**: Keep Properties descriptive and unindexed. Preserve their scalar-codec format, broad type domain, case-insensitive names, defensive snapshots, null-preserve/empty-clear rules, and separation from private transform metadata. A property alone never matches a dimension filter.
- **REQ-002**: Give each feature its own collection, values, filters, validation, capabilities, errors, serializers, name dictionary, EF value entities, resolver, translator, and tests. Reuse general Common results, hashing, scalar codecs, metrics, and continuation protection. Introduce no shared Dimensions engine, AST, entity base, normalizer, or dictionary.
- **REQ-003**: Support public `int`, `decimal`, `bool`, `string`, UTC `DateTime`, and explicit null only. Missing means no entry/row. Reject other types and invalid inputs before mutation; do not coerce, round, truncate, or silently omit them.
- **REQ-004**: Automatically index every accepted supplied Dimension on capable providers. Applications supply names and values without registration, index selection, or NameIds. Existing Properties are never promoted implicitly.
- **REQ-005**: On insertion, omitted/empty Dimensions creates no snapshot, name registrations, or values. On content replacement, null/omitted preserves, empty clears, and non-empty replaces. `UpdateDimensionsAsync` requires a non-null replacement collection; empty clears. Properties/expiration-only operations preserve Dimensions without dictionary/value access.
- **REQ-006**: Use one whole-item ETag for content, Properties, expiration, and Dimensions. A mutation of any of these invalidates earlier conditions for the others. Preserve exact caller conditions, create-only checks, missing-item behavior, acknowledged-version responses, bounded internal preservation attempts, cancellation, guarded compensation, and ordered batch prefix outcomes. Never refresh a supplied ETag or retry a conflict unconditionally.
- **REQ-007**: Per feature, add one name table and one value table, plus nullable parent `DimensionsJson` mapped to physical `Dimensions`. The snapshot contains original names and typed logical values, not NameIds. Maintain snapshot, registrations, value deltas, and owner version atomically. Ordinary metadata reads use the snapshot and cause no per-result dictionary/value query.
- **REQ-008**: A dictionary row contains database-generated `long Id`, original bounded `Scope`/`Name`, and 32-byte SHA-256 `ScopeHash`/`NameHash`. Unique key: `(ScopeHash, NameHash)`. Verify original logical identities after lookup; collisions fail atomically. No normalized-name column, ID reuse, per-value counters, or name deletion during owner cleanup.
- **REQ-009**: Scope dictionary identities by physical store and persisted blob container/document type. Document partitions remain parent constraints. Do not substitute a named-client identity. There is no dictionary-name quota; applications manage cardinality and unused names remain retained.
- **REQ-010**: Value PKs are `(BlobId, NameId)` and `(DocumentId, NameId)`. Each value has `ValueType` and exactly one populated non-null search slot, or no populated slot for explicit null. Integer/Boolean/UTC ticks share `long? IntegralValue`; decimals use `decimal? DecimalValue`; strings use encoded `StringValue`.
- **REQ-011**: Declare three ordinary value search indexes per feature: `(NameId, ValueType, IntegralValue, OwnerId)`, `(NameId, ValueType, DecimalValue, OwnerId)`, and `(NameId, ValueType, StringValue, OwnerId)`. Dictionary PK/unique indexes and value PKs are additional. Every ordinary search index includes null-slot rows; measure their costs and remove redundant convention indexes.
- **REQ-012**: Dimension comparisons require the same logical type. Inequality matches only present, non-null values of that type. Unknown names do not register during reads. Exists, missing, null, and non-null are explicit states. Support bounded AND/OR; exclude general NOT, string ordering/search, payload fields, and dimension-based result sorting.
- **REQ-013**: Filter in SQL before limiting/counting. Preserve logical-key order, keyset continuation, document visibility cutoff/expiration, scope, and authorization. Bind tokens/cache keys to logical canonical predicates, not NameIds. Positive index anchors may replace a prefix/exact-key anchor; each OR branch must independently satisfy broad-query consent rules.
- **REQ-014**: Advertise persistence separately from per-kind/operator query support. Only qualified relational EF engines support Dimensions. InMemory, Azure Blob/Table, filesystem, Cosmos/EF Cosmos, EF InMemory, and unqualified EF engines reject explicit Dimensions, including empty collections, filters, and dedicated updates before I/O. Omitted inputs retain existing behavior.
- **REQ-015**: Propagate Dimensions through existing helpers, transforms, caches, batch operations, copy/move, HTTP, console, diagnostics, and client accessors. A dimensions-only update must not read/rewrite payload bytes or change Properties, transform state, expiration, or content hash.
- **SEC-001**: Parameterize SQL and never extract JSON, hash, cast, or apply collation functions to indexed value columns. Values are searchable metadata outside payload encryption; never log their contents or use dimension names as unbounded metric labels.
- **CON-001**: Use standard EF annotations and conventions for new relational models: `[Table]`, `[Column]` for the snapshot name, `[Key]`/`[PrimaryKey]`, `[DatabaseGenerated]`, `[Required]`, `[MaxLength]`, `[Unicode]`, `[Precision]`, `[Index]`, `[ForeignKey]`/`[InverseProperty]`, and `[NotMapped]` where needed. No Dimensions model-builder call, custom convention, filtered/computed/expression index, INCLUDE, trigger, procedure, hard-coded SQL type, or hand-authored schema DDL.
- **CON-002**: Preserve `IBlobStoreContext` and `IDocumentStoreContext` members. Discover value/name entities through parent navigations and access them using `DbContext.Set<TEntity>()`. Gate this choice with blob-only, document-only, and combined contexts. A failed discovery or unsupported-engine proof blocks dependent phases. Accepted exception: Cosmos contexts call ExcludeDocumentDimensions to exclude the two relational members; SQL contexts require no new configuration.
- **CON-003**: Breaking new Dimensions APIs/context adoption is allowed. Use generated initial schemas for new test/development resources. Do not implement data backfill, Properties conversion, compatibility readers, upgrade workers, or changes to the completed Properties alignment formats. Test migration generation separately for each engine; do not ship an old-data upgrade workflow.
- **CON-004**: Keep Domain projects unchanged. Use the current SDK/packages from `global.json`, `Directory.Build.props`, and `Directory.Packages.props`; do not update dependencies as part of this feature. Run top-level builds/tests sequentially in this worktree. Parallel task eligibility never authorizes concurrent writes to the same files or concurrent builds.
- **CON-005**: Provide capability-aware dashboard Dimension query controls; Dimension mutation editing remains outside scope. Preserve existing dashboard draft/ETag conflict handling and metadata projection. Dashboard filter URLs remain subject to the accepted hosting request-size limits. Use fictional domain examples in documentation. Do not commit/push or publish PR changes unless separately authorized.
- **PAT-001**: Use feature-owned `Result` errors, asynchronous I/O with cancellation, bounded materialization/tracking, existing lease/transaction boundaries, general scalar codecs, and protected continuation tokens. Avoid per-dimension/per-result round trips, global locks, payload buffering, and unbounded owner-ID lists.

Execution constants are fixed for this plan:

| Identifier | Value and validation |
| --- | --- |
| LIM-001 | Name grammar `\A[A-Za-z_][A-Za-z0-9_.:-]{0,127}\z`; 1..128 ASCII characters. Canonicalize ASCII lowercase to uppercase without trimming; reject canonical duplicates. Preserve supplied spelling in snapshots. |
| LIM-002 | Scope maximum 256 UTF-16 code units; use existing persisted container/type identity rules. SHA-256 digests are exactly 32 bytes. |
| LIM-003 | Decimal precision 18, scale 6; range `-999999999999.999999` through `999999999999.999999`. Accept redundant fractional zeros; reject required rounding and overflow. Canonical query operands use invariant numeric identity. |
| LIM-004 | String maximum 256 strict UTF-8 bytes; reject unpaired UTF-16 surrogates. Preserve case, spaces, normalization forms, embedded nulls, and empty string. Store uppercase `Convert.ToHexString` search text with `[MaxLength(512)]`, `[Unicode(false)]`; retain original text in the snapshot. |
| LIM-005 | `DateTimeKind.Utc` only; store exact ticks in `IntegralValue`. Integer decode must fit Int32; Boolean decode accepts 0/1 only; ticks must fit DateTime. |
| LIM-006 | Maximum 64 entries/owner including null, 16 predicates/filter, 16 groups/filter, four group levels. Root group is level one; a standalone predicate has no group level. Reject empty groups. |
| LIM-007 | Per physical-store provider instance and feature: 4,096 positive cache entries across scopes, four concurrent mutations registering new names, at most three registration race-resolution attempts, at most 64 names/write batch. No negative cache or name quota. Existing-name writes acquire no registration permit. |
| LIM-008 | Persist separate byte-backed enums with fixed values `Null=0`, `Integer=1`, `Decimal=2`, `Boolean=3`, `String=4`, `DateTime=5`. Predicates always constrain the logical discriminator. |

Initial operator profiles, enabled only after their proof/tests pass:

| Operation | SQL Server / PostgreSQL | SQLite |
| --- | --- | --- |
| Integer and UTC DateTime equality, inequality, ranges | Indexed slot predicates | Indexed slot predicates |
| Boolean equality/inequality | Indexed slot predicates | Indexed slot predicates |
| Decimal equality | Indexed slot predicate | Indexed exact equality, mandatory proof |
| Decimal inequality/ranges | Indexed slot predicates | Unsupported |
| Exact string equality/inequality | Indexed encoded-string predicates | Indexed encoded-string predicates |
| Exists/missing/null/non-null and bounded AND/OR | Backend execution | Backend execution |
| String ordering, general NOT, substring/payload search | Unsupported | Unsupported |

Indexed eligibility is not a selectivity or constant-latency guarantee. Broad negative/common-value queries and counts retain consent rules and separate measurements.

## 3. Alternatives

- **ALT-001**: Query or promote Properties JSON. Rejected because Properties is independent descriptive metadata with a broader scalar domain and unchanged persistence behavior.
- **ALT-002**: Indexed computed JSON paths or predefined business columns. Rejected because runtime names must not require schema changes or per-property declarations.
- **ALT-003**: Five value tables or five typed indexes. Rejected in favor of one value table and three slots per feature, while preserving logical type discrimination.
- **ALT-004**: Repeat name strings/hashes in every value row. Rejected because a scoped generated NameId reduces repeated hot-index material at high value counts.
- **ALT-005**: Use raw string equality under backend collation or decimal-to-double conversion. Rejected because they change exact case/space/numeric semantics. Uppercase UTF-8 hexadecimal and exact decimal equality require real-engine proof.
- **ALT-006**: Filtered/computed indexes, Fluent API schema configuration, a shared Dimensions subsystem, or application-side scan filtering. Rejected by the annotation, feature ownership, and backend-query requirements.
- **ALT-007**: Add a dictionary-name quota or shared reference counter. Rejected by the final decision pass. Keep name cardinality application-managed and bound caches/individual operations instead.
- **ALT-008**: Add cloud/filesystem shadow catalogs, InMemory evaluation, old-data migration, or Properties backfill. Excluded from this implementation.

## 7. Risks & Assumptions

- **RISK-001**: SQLite decimal equality may translate through a function/collation or persist numerically equal scales differently. TASK-008 is a blocking proof; preserve exact values and seek an explicit design revision if the accepted indexed representation cannot pass.
- **RISK-002**: Uppercase UTF-8 hexadecimal doubles byte count before indexing. SQL Server index width and PostgreSQL/SQLite physical plans must be measured with owner locator bytes and actual collations. A successfully created index is insufficient evidence.
- **RISK-003**: New parent navigations can change entity discovery on EF Cosmos or other unsupported engines. The annotation-only relational setup and unchanged unsupported-engine operations must both hold; do not hide a new host configuration requirement or broaden Dimensions support to resolve a failing probe.
- **RISK-004**: New-name races interact with PostgreSQL aborted transactions, SQL Server unique-key contention, and SQLite writer serialization. Per-instance limits are resource bounds, not distributed locks. Multiple instances must still converge through database uniqueness and atomic owner commits.
- **RISK-005**: Dictionary cardinality is intentionally unbounded. Immutable retained entries accumulate even after owners are deleted. Diagnostics expose this growth without a quota, a per-write count, or a hotspot counter.
- **RISK-006**: Snapshot duplication, three full ordinary indexes, broad result sets, logical-key ordering, and counts can dominate latency/storage. The accepted million-owner workload is a qualification target, not a constant-speed guarantee or evidence for larger datasets.
- **RISK-007**: Static registration metadata can disagree with the actual EF engine or DI lifetime. TASK-013/027 must prove metadata/profile consistency without SQL or application-managed provider selection.
- **RISK-008**: Cached snapshots, transform-created replacement objects, helper option copies, and document batch paths can silently drop Dimensions or caller ETags. TASK-019..026 require explicit propagation and race tests.
- **RISK-009**: Raw blob uploads carry optional typed Dimensions in headers and inherit hosting header limits. Reject oversize/invalid metadata explicitly; the .NET client's collection limit is not an HTTP-header capacity guarantee. Search uses JSON request bodies to avoid complex filter query-string limits.
- **RISK-010**: External engines, emulator availability, plan permissions, and reference hardware may be missing locally. Record incomplete evidence, retain the gate, and never fabricate an environmental qualification pass.
- **ASSUMPTION-001**: No deployed Dimensions clients or stored Dimensions data require compatibility or backfill. Existing Properties and current storage content remain valid and unchanged.
- **ASSUMPTION-002**: The accepted final decisions and existing whole-item ETag contract are authoritative. Routine file/API implementation details above may be implemented directly; a failed proof that requires changing those decisions must leave dependent tasks blocked with evidence.
