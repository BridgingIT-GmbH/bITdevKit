# Introduction

![Status: In progress](https://img.shields.io/badge/status-In%20progress-yellow)

This execution plan implements [spec-worktree-development-isolation.md](../docs/specs/spec-worktree-development-isolation.md). Every `DevKitWebApplicationBuilder` host activates it by default (DEV-018). When it starts in eligible local development from a Git linked worktree, it gets its own slot, ports, SQL Server catalogs, cookies, data-protection keys and file roots. Ordinary checkouts, production, tests, build-time generation and containers keep today's behavior. The `bdk dev` command group manages slots and resources.

The specification is authoritative. When this plan and the specification disagree, follow the specification and correct this plan. All tasks start incomplete. Source paths and line numbers were inspected at commit `3dc16a20e`; re-check line numbers before editing. Repository example applications (DoFiesta, WeatherFiesta) are named here as first adopters only. Documentation under `docs/` must use fictional applications.

## 1. Requirements & Constraints

- **REQ-001**: The feature lives on `DevKitWebApplicationBuilder` only. No plain `WebApplicationBuilder` overload. It activates by default at the first configuration consumer (DEV-018). Order: `DevKitWebApplication.CreateBuilder(args)` → `AddConfiguration()` → optional `AddDevAppInstance(...)` → logging → modules, authentication, fake IdP, dashboard, resources → `Build()`.
- **REQ-002**: Eligibility is evaluated in this order and stops at the first failure: (1) feature registered and `DevAppInstance:Mode` is not `Disabled`; (2) not build-time OpenAPI generation (`EnvironmentExtensions.IsBuildTimeOpenApiGeneration()`); (3) `IHostEnvironment.IsDevelopment()`; (4) not containerized and not cloud. Test hosts fail condition 3. Failing any condition yields an inactive context with a reason. Inactive hosts never invoke Git or touch the registry.
- **REQ-003**: Git detection walks up from the content root to the first `.git` entry. A `.git` directory means ordinary checkout. A `.git` file is parsed for `gitdir:`; a target that has a `commondir` file and a `gitdir` back-pointer to this checkout is a linked worktree; a target without `commondir` (submodule, `--separate-git-dir`) is ordinary. No `.git` entry means not a repository (inactive). `GIT_*` environment variables are ignored. Paths compare case-insensitively on Windows and case-sensitively on Linux, after symlink resolution.
- **REQ-004**: When file detection is inconclusive (stale back-pointer, unreadable metadata), startup and `bdk dev` run the Git fallback: `git rev-parse --show-toplevel`, `git rev-parse --git-dir`, `git rev-parse --git-common-dir`, with a 5-second timeout each, `GIT_*` variables removed from the child environment, paths passed as literal arguments, no remote access. The EF design-time factory never starts Git and fails with `worktree_detection_failed`.
- **REQ-005**: The local assignment file `.dev/instance.json` contains `{ "version": 1, "worktreeId": "<uuid>", "slot": <1..49> }`. The registry `<git-common-dir>/bdk-dev/instances.json` is authoritative. It records assignments (worktree ID, slot, canonical path, assignment timestamp), catalog entries, the port policy and an inventory copy per application (application ID, project path relative to the repository root, sanitized server identity, generated catalog names). Unknown JSON properties are preserved on rewrite. A higher `version` than supported fails with `assignment_invalid`, names the minimum package version and writes nothing.
- **REQ-006**: Registry writes take an exclusive cross-process lock (lock file opened with `FileShare.None`) with a 10-second timeout that fails with `registry_locked`, then replace the file atomically (write temp file, `File.Replace`/`File.Move(overwrite: true)`). Invalid JSON, duplicate slots or conflicting local files fail without rewriting. A crash between registry commit and local-file write recovers the same slot.
- **REQ-007**: Catalog entries are declared in code: application ID matching `^[a-z][a-z0-9-]{0,62}$` (optional since DEV-015, derived from the application name), database prefix matching `^[A-Za-z][A-Za-z0-9_]{0,31}$` (default: PascalCase of the ID, hyphens removed), HTTP and HTTPS offsets (optional since DEV-015, assigned by the registry). A second application declaring a recorded ID, prefix or offset, or a changed own declaration, fails with `configuration_conflict` naming both applications and `bdk dev configure --forget-app <id>`.
- **REQ-008**: Default port policy: `BasePort = 5000`, `BlockSize = 100`, `SlotCount = 49`. Slot base port is `BasePort + BlockSize * slot`. Offsets must be `< BlockSize`. Bind to loopback only. The allocator skips a slot when any catalog port in its block is in the denylist `{5341, 5432, 5672}`, in an OS-excluded range (Windows: parse `netsh int ipv4 show excludedportrange protocol=tcp`), or not bindable on `IPAddress.Loopback` and `IPAddress.IPv6Loopback`. Skipped slots are logged at Debug. All slots unavailable fails with `slots_exhausted`. A blocked port on an existing assignment fails with `port_in_use`, states whether the port is OS-reserved, and names `bdk dev release` plus a fresh start.
- **REQ-009**: Configuration inputs: `DevAppInstance:Mode` (`Auto` default, `Disabled`) and `DevAppInstance:Slot` (optional int). A slot in an ordinary checkout fails with `configuration_conflict`. An explicit slot owned by another worktree fails with `slot_in_use`. An explicit slot that differs from an existing assignment fails with `assignment_invalid` and names `bdk dev configure`.
- **REQ-010**: D7 URL handling in managed mode: replace `urls`, `http_ports`, `https_ports`, `https_port` and their `ASPNETCORE_`/`DOTNET_` environment forms plus `--urls` with the resolved values, and log the replaced value at Information. A configured `Kestrel:Endpoints` section fails with `configuration_conflict`. After start, compare `IServerAddressesFeature.Addresses` with the resolved URLs; a mismatch logs `configuration_conflict`, releases the lease and stops the host with exit code 1.
- **REQ-011**: Managed values are an in-memory configuration source appended to `builder.Configuration` at registration. Managed keys: D7 URL keys, `https_port`, `Authentication:Authority`, declared authority/issuer keys, keys mapped by resource declarations, file-path keys. `Build()` moves the managed source last, compares every managed key's effective value with the resolved value, and fails with `configuration_conflict` naming the key and expected non-secret value.
- **REQ-012**: SQL Server catalogs are `<Prefix>_w<slot:00>_<ModuleId>`, set through `SqlConnectionStringBuilder.InitialCatalog` on the ordinary connection string (server and credentials unchanged). Names longer than 128 characters fail validation. At `Build()`, any effective configuration value that parses as a SQL Server connection string with the same data source and catalog as a declared baseline, and is neither declared nor marked shared, fails with `configuration_conflict` naming the key only. `DeleteOnStartup`/`EnsureTruncated` act on the instance catalog. `DatabaseCreatorService` and `DatabaseMigratorService` are unchanged. No catalog ownership guard is added; reset and prune touch only catalog names recorded in the inventory.
- **REQ-013**: The SQL Server design-time factory uses `--connection-string=` when given. Otherwise, in a linked worktree, it reads `.dev/state/<appId>/inventory.json`, selects the entry for the factory's connection key, and uses its catalog. A missing inventory, missing entry or ambiguous entry fails without connecting.
- **REQ-014**: Each application's state root is `<worktree>/.dev/state/<appId>/` with `payload/`, `logs/`, `keys/` and an ownership marker `.bdk-owner.json` (`{version, appId, worktreeId}`). Mutation and reset refuse a missing or mismatched marker with `resource_not_owned`, and refuse symlink or reparse-point escapes before recursive deletion. Reset clears `payload/` only; keys survive.
- **REQ-015**: Serilog: add enrichers `DevAppInstanceAppId`, `DevAppInstanceWorktreeId`, `DevAppInstanceSlot` in managed mode. `Serilog:WriteTo` database sinks must be declared (mapped), marked shared, or disabled; otherwise the ordinary-catalog guard fails startup. OpenTelemetry configuration is unchanged.
- **REQ-016**: One lifetime lease per application per worktree in `<git-common-dir>/bdk-dev/leases/<worktreeId>.<appId>.lock`, held open with `FileShare.None` for the process lifetime. Acquisition retries for 5 seconds with Debug logs, then fails with `instance_running`. The lease is acquired before resource initialization. `dotnet watch` restarts reacquire it.
- **REQ-017**: `HostRuntimeDescriptor` gains an optional `DevAppInstance` property serialized as `devAppInstance { appId, worktreeId, slot, httpUrl, httpsUrl, processStartedAt, leasePath }`. The schema version does not change. The descriptor writer runs when `DevKitLocalToolingPolicy` enables tooling or isolation is active.
- **REQ-018**: Authentication in managed mode: call `WithIssuer` with the resolved HTTPS origin on the fake IdP; a configured loopback issuer on another origin fails with `configuration_conflict`; an external issuer is unchanged. A shared redirect normalizer resolves origin-relative redirect and post-logout URIs against the request origin at the authorize endpoint, logout endpoint and sign-in page, and in client listings. Absolute non-loopback URIs keep exact match. An absolute loopback URI on another origin fails validation.
- **REQ-019**: Cookie names in managed mode: `.Bdk.Dashboard.<appId>.w<NN>` and `.Bdk.FakeIdentityProvider.<appId>.w<NN>`. Every other cookie authentication scheme, the session, antiforgery and cookie temp-data cookies gain the same suffix (`DevAppInstanceCookieIsolation`). Data protection uses application name `<appId>.w<NN>` and persists keys to `<state>/keys`, composed through options.
- **REQ-020**: Hosted WASM clients use a relative `Authentication:Authority` resolved against `HostEnvironment.BaseAddress` (DEV-020). The feature maps no browser configuration endpoint.
- **REQ-021**: Inactive footprint: only the immutable context singleton (`IsActive = false`, reason) is registered. No files, configuration source, `Build()` validation, hosted services, leases, adapters or endpoint. The reset argument is refused with a nonzero exit and an error log.
- **REQ-022**: `bdk dev` commands: `configure --slot N`, `configure --forget-app <id>`, `status [--json]`, `stop --app <id>`, `reset --app <id> --confirm-instance <id>:w<NN>`, `release --confirm-slot N`, `prune [--confirm] [--json]`. The CLI never loads application assemblies or reads secrets.
- **REQ-023**: Startup log uses log key `BDK`, template `[BDK] worktree <message> (<prop>=<value>)`. Managed start writes Information entries for Mode, Slot (new/existing/recovered), URLs, Databases, Database lifecycle, Authentication, Data protection, Listener and Duration, then one ready summary whose first line is the HTTPS URL (Open, HTTP, Dashboard, Issuer, Databases, Worktree, Note). A failure before host build writes the error line to standard error. An inactive host writes at most one Debug entry.
- **REQ-024**: IIS: when `ASPNETCORE_IIS_PHYSICAL_PATH` is set and detection yields a linked worktree, fail with `unsupported_host` before any database connection. Ordinary checkouts under IIS are unchanged.
- **SEC-001**: Credentials, secret-bearing connection strings and key material never appear in status text, `--json` output, error messages, startup log entries or the inventory. Sanitize server identity as `DataSource` only.
- **SEC-002**: Removed by DEV-020; there is no browser projection.
- **SEC-003**: `bdk dev stop` kills a process only after verifying PID, process start time and lease path from the descriptor. A reused PID is refused.
- **SEC-004**: Detection or allocation failure never falls back to the ordinary database, ports or files.
- **ERR-001**: Error codes are exactly: `worktree_detection_failed`, `slots_exhausted`, `assignment_invalid`, `slot_in_use`, `registry_locked`, `instance_running`, `port_in_use`, `configuration_conflict`, `unsupported_host`, `resource_not_owned`, `reset_incomplete`.
- **CON-001**: Core contracts and implementation live in `src/Common.Utilities/DevAppInstances/` (namespace `BridgingIT.DevKit.Common`). `Common.Utilities` is referenced by `Presentation.Cli`, `Presentation.Web`, `Presentation.Web.Client`, `Infrastructure.EntityFramework` and (through `Application.Storage`) `Infrastructure.FileSystem`, and it already references `Common.Results`. No new project is created.
- **CON-002**: Core code has no ASP.NET Core, EF Core or SqlClient dependency. SQL Server code lives in `Infrastructure.EntityFramework` / `Infrastructure.EntityFramework.SqlServer`. Filesystem code lives in `Infrastructure.FileSystem` or core when it only manages the state root.
- **CON-003**: Declaration APIs are pure data. They do not resolve services, open connections or read files when called.
- **CON-004**: Slots are per repository. No machine-wide port ledger.
- **CON-005**: Existing integration fixtures, Testcontainers tests and build-time OpenAPI generation run unchanged and claim no slots.
- **CON-006**: Nullability annotations stay disabled. Use file-scoped namespaces, `this.` for fields, no underscores, XML docs with usage examples on public symbols, one blank line between public members (see `AGENTS.md` and `.editorconfig`).
- **GUD-001**: Return `Result`/`Result<T>` for recoverable failures from resolver, stores and adapters. Throw `DevAppInstanceException` (carrying `Code`) only at the host composition boundary to stop startup.
- **GUD-002**: Use `TimeProvider` for timestamps and timeouts so tests can control time.
- **GUD-003**: Tests use temporary Git repositories, OS temp directories and disposable SQL Server catalogs. Tests never touch the developer's registry, databases or running hosts.
- **PAT-001**: CLI commands follow `src/Presentation.Cli/Commands/HostRunCliCommand.cs`: derive from `CliGroupedConsoleCommandBase("dev", "<name>", "<description>")`, options via `[ConsoleCommandOption(...)]`, override `ExecuteAsync(IAnsiConsole, IServiceProvider, CancellationToken)`, register in a module in `src/Presentation.Cli/CliHost/CliCommandModules.cs` with `registry.AddGroup("dev", ..., group => group.WithCommand<...>())`, and add the module in `src/Presentation.Cli/CliHost/CliApplication.cs:196-200`. JSON output uses `CliJson`; exit codes use `CliExitCode`.
- **PAT-002**: Builder extensions follow `src/Presentation.Configuration/DevKitWebApplicationBuilderExtensions.cs` (`AddConfiguration<TBuilder>`).
- **PAT-003**: Cookie renaming uses `services.AddOptions<CookieAuthenticationOptions>(scheme).PostConfigure<IServiceProvider>(...)` registered inside `AddDashboardAuthentication` and `AddFakeIdentityProvider`, reading the optional `DevAppInstanceContext` singleton. This works regardless of registration order.

### Implementation deviations

- **DEV-001**: Registration and resolution errors throw `DevAppInstanceException` with a stable code instead of returning `Result<T>` (TASK-002), because startup must stop before the host is built.
- **DEV-002**: The REST per-user environment file (TASK-001, TASK-052) was not implemented. The `.http` files keep their ordinary `@baseUrl`; developers use `bdk dev status` or the startup log.
- **DEV-003**: `.vscode/launch.json` keeps the explicit `--urls` arguments (TASK-052). Managed mode replaces them in linked worktrees; only the `serverReadyAction` patterns were generalized.
- **DEV-004**: Serilog enrichment (TASK-033) is applied through managed `Serilog:Properties:*` configuration values instead of changes to `HostBuilderExtensions.ConfigureLogging`.
- **DEV-005**: `bdk dev stop` writes a `.stop` request file next to the lease for graceful shutdown and waits `--timeout` seconds (default 45). `--force` kills only after the process ID and start time match. `ProcessStartedAt` was added to the descriptor and lease info.
- **DEV-006**: Reset does not check catalog ownership markers; it relies on the inventory and the generated naming formula.
- **DEV-007**: Identity authorities are rewritten only for loopback ordinary authorities; token issuer validation uses the normalized issuer.
- **DEV-008**: `bdk dev` uses the global `--output json` option instead of a `--json` flag. `reset` and `prune --confirm` pass through the host exit codes `2` (refused) and `3` (incomplete).
- **DEV-009**: `InternalsVisibleTo` for `BridgingIT.DevKit.Presentation.UnitTests` was added to `Presentation.Cli.csproj` for `DevCliCommandTests`.
- **DEV-010**: The tool-versus-package version warning (TASK-053) is not implemented yet; the guide tells adopters to keep both versions equal.
- **DEV-011**: Types and keys are named `DevAppInstance*` (`AddDevAppInstance`, `DevAppInstance:Mode`, descriptor property `devAppInstance`) instead of `DevelopmentInstance*`.
- **DEV-012**: Host descriptors gained a general `urls` list, rewritten on `ApplicationStarted`, and `devAppInstance.worktreeRoot`. `bdk hosts list/current` and the `bdk mcp` runtime tools return `url`, `urls` and `devAppInstance`. Discovery matches hosts by worktree root, treats a `.git` file as a workspace root and rejects a reused process ID through `processStartedAt`.
- **DEV-013**: Database isolation uses discovery instead of key mapping. `MapSqlServerDatabase`, `ShareSqlServerConnection` and the application database prefix were removed. `WithSqlServerDatabases()`, `WithPostgresDatabases()` and `WithSqliteDatabases()` register adapters derived from `DevAppInstanceDatabaseAdapterBase`. They manage every key whose path contains `ConnectionString` and name instance databases `<database>_wNN` (SQLite inserts the suffix before the file extension). `ShareConnectionString(key)` keeps a key shared. All three design-time factories resolve through the inventory slot.
- **DEV-014**: `With<Provider>Databases()` is optional. Each provider assembly declares `[assembly: DevAppInstanceDatabaseAdapter(...)]`; `AddDevAppInstance` locates the adapters in the Development environment through `DevAppInstanceDatabaseAdapterLocator`, which loads the three DevKit provider assemblies by name. Location happens before logging, so the Serilog SQL sink gets the instance database. As a fallback, `Add{SqlServer,Postgres,Sqlite}DbContext` call `DevAppInstanceSession.ResolveConnectionString`, which plans an unknown adapter kind late and writes the managed values into the mutable `DevAppInstanceConfigurationSource`. The examples no longer call `WithSqlServerDatabases()`.
- **DEV-015**: `WithApplication` is optional (REQ-007 changed). `WithApplication(string appId = null, int? httpOffset = null, int? httpsOffset = null)`; `AddDevAppInstance()` has a parameterless overload. A missing ID derives from `IHostEnvironment.ApplicationName` through `DevAppInstanceApplication.DeriveAppId` (trailing `Server/Web/Presentation/Api/WebApi/Host/Service` segments dropped, last segment lowercased, `[^a-z0-9]+` → `-`, `app-` prefix for a leading digit). The ID limit is 63 characters (`^[a-z][a-z0-9-]{0,62}$`); a longer derived ID is cut and ends with 8 hex characters of SHA-256 of the full name. Missing offsets set `HasAutomaticOffsets`; `ValidateCatalog` reuses the recorded pair or records the lowest free pair `(2k, 2k+1)` within the block size. The registry stores `source` for derived IDs; two different sources with the same ID fail with `configuration_conflict`. One declared offset implies the adjacent other. Both examples call `AddDevAppInstance()` and reuse their recorded entries.
- **DEV-016**: `WithApplication` is replaced by two order-independent builder methods: `WithAppId(string appId)` and `WithHttpOffset(int http, int? https = null)`. `https` defaults to `http + 1`; calling `WithHttpOffset` clears `HasAutomaticOffsets`. A host with only `WithHttpOffset` still derives its ID. Usage: `.AddDevAppInstance(o => o.WithAppId("forecasthub").WithHttpOffset(http: 10, https: 11))`.
- **DEV-017**: `WithBrowserClient` and `MapFileSystemPath` are removed. The client ID and file paths have the same value in every worktree. `/_dev/instance-config` returns `appId`, `slot`, `origin` and `authority`; `AddDevAppInstanceConfigurationAsync(authorityKey)` overrides only the authority. Relative file paths already resolve inside each worktree's content root; absolute paths stay shared, and the guide recommends relative paths. `FileSystemPathDevAppInstanceAdapter` and the `filesystem` adapter kind are gone, so `bdk dev reset` drops databases only. `PayloadRoot` remains on the context for custom adapters.
- **DEV-018**: Default-on activation (REQ-001 changed). `#if DEBUG` is not usable because DevKit ships as Release packages, so the existing gate decides: Development environment, linked worktree, not container, cloud or build time. The `DevKitWebApplicationBuilder` constructor registers a `DevAppInstanceActivation` singleton and sets `DevKitBuilderProperties.ConfigurationCompletion`. `CompleteConfiguration()` runs it once from `AddLogging`, `AddModules`, `GetDevAppInstance` and `Build()`; `DevAppInstanceSession.ResolveConnectionString` runs it from `Add<Provider>DbContext`. `AddConfiguration` does not trigger it. `AddDevAppInstance` cancels the default activation; called after activation it throws `InvalidOperationException`. `DevAppInstanceBuilder.Enabled(false)` registers an inactive context with reason `disabled`. The static `RequestCustomizer` test seam became a per-builder property. The examples no longer call `AddDevAppInstance`. Smoke: weatherfiesta activated without the call on w01, ports 5110/5111, database `_w01`.
- **DEV-019**: New `bdk dev run [--app a,b] [--no-build]` convenience command (`DevRunCliCommand`, `DevAppInstanceCliService.RunAsync`). `DevAppInstanceHostProjects` finds hosts from registry inventory project paths (keeps `WithAppId` IDs) plus a scan for `Microsoft.NET.Sdk.Web` projects calling `DevKitWebApplication.CreateBuilder` (ID from the assembly name; skips `bin`, `obj`, `node_modules`, dot folders, nested checkouts). Without `--app` all hosts start. Unknown IDs fail with `app_not_found`; held leases are skipped. Builds run sequentially, then hosts run concurrently with `dotnet run --no-build` and their launch profile; output lines are prefixed `[appId]`. `IDevAppInstanceProcessRunner.RunStreamingAsync` keeps the child on the CLI console so Ctrl+C reaches it; the command also writes stop requests for managed instances, waits 30s, and a second Ctrl+C or the timeout kills the process trees. Works in ordinary checkouts too. Smoke: `bdk dev run --app weatherfiesta` started w01 on 5111, a second run skipped it, `bdk dev stop` ended it with exit code 0.
- **DEV-020**: `/_dev/instance-config`, `DevAppInstanceStartupFilter`, `DevAppInstanceContext.ToBrowserConfiguration`, `DevAppInstanceBrowserConfiguration` and `AddDevAppInstanceConfigurationAsync` (with its tests) are deleted. A hosted WASM client is served by the host that issues its tokens, so a relative authority resolved against `HostEnvironment.BaseAddress` already points at the slot origin. DoFiesta's client uses `"Authority": "/"` and resolves it in `AddOidcAuthentication`. The server keeps managing its own `Authentication:Authority`.

## 3. Alternatives

- **ALT-001**: Random ports. Rejected: unpredictable addresses and identity callbacks.
- **ALT-002**: Branch-name or path hashing without a registry. Rejected: collisions, and identity changes when paths or branches change.
- **ALT-003**: One SQL Server instance per worktree. Rejected: startup time and memory; catalogs meet the isolation requirement.
- **ALT-004**: Repository PowerShell launcher. Rejected: duplicates host discovery and is not reusable by external adopters; `bdk dev` replaces it.
- **ALT-005**: CLI loads provider adapters directly. Rejected: requires application secrets and provider packages; reset runs inside the host.
- **ALT-006**: Rewritten `wwwroot/appsettings.json`. Rejected: tracked file shared by checkouts and cached by browsers.
- **ALT-007**: Hostnames plus reverse proxy. Rejected for the first version: DNS, certificate and proxy setup.
- **ALT-008**: Warn in unregistered hosts that run in linked worktrees. Rejected: puts detection into every host for an unlikely case.
- **ALT-009**: New `Common.DevAppInstances` project. Rejected in favor of `Common.Utilities` (CON-001), which every consumer already references.

Startup, design-time factory and `bdk dev` agree. `GIT_DIR` set in the environment does not change the result.
- **TEST-004**: Git invocation: conclusive layouts start no process; stale back-pointer triggers fallback at startup and `worktree_detection_failed` in the design-time path; paths with spaces; missing Git, nonzero exit, timeout and invalid output map to `worktree_detection_failed`.

## 7. Risks & Assumptions

- **RISK-001**: Composition code that reads a managed key before activation cannot be detected. Mitigation: the guide names the activation points and tells such hosts to call `AddDevAppInstance()` early; `Build()` validation catches later shadowing.
- **RISK-002**: Windows file locking semantics differ from Linux for lock and lease files. Mitigation: use `FileShare.None` handles on both and run TEST-007/TEST-021 on both platforms in CI.
- **RISK-003**: `netsh` parsing is locale-dependent. Mitigation: parse numeric columns only; treat parse failure as "no reserved ranges" and rely on the bindable check.
- **RISK-004**: Preventing the listener from starting in reset mode depends on `IHostedLifecycleService` ordering. Mitigation: TEST-025 asserts no port is bound during reset.
- **RISK-005**: Moving container/cloud checks into `Common.Utilities` may create ambiguous extension calls. Mitigation: keep `Presentation` members as forwarders with identical signatures in their existing namespace and build the full solution.
- **RISK-006**: Different repositories on one machine can share slot ports (CON-004). Mitigation: `port_in_use` names `bdk dev configure --slot` and `release`.
- **ASSUMPTION-001**: One installed `bdk` tool version serves the ordinary checkout and all linked worktrees of a repository.
- **ASSUMPTION-002**: Developers use one SQL Server instance per repository; catalog names identify instance databases without an ownership guard.
- **ASSUMPTION-003**: Changing a model in a worktree is handled by the app's `DatabaseCreatorService` with `DeleteOnStartup` or by `DatabaseMigratorService`; isolation does not detect schema drift.
- **ASSUMPTION-004**: OpenTelemetry exporters and endpoints need no per-worktree change.
