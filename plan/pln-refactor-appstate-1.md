# Introduction

![Status: Completed](https://img.shields.io/badge/status-Completed-brightgreen)

Refactor the existing AppState abstraction in `src/Presentation.Web.Client/AppState/` so it can support independent component instances, Server circuits, browser runtimes, persisted preferences, and selector subscriptions. Deliver and validate these capabilities before the Blazor presentation framework exists. Keep the existing package, namespace, derived-state pattern, constructor signatures, events, and ordinary fluent registration path.

The work is confined to Presentation, its tests and benchmarks, and AppState documentation. It reuses .NET DI, cancellation, `TimeProvider`, `System.Text.Json`, `ILogger`, existing Result types, BenchmarkDotNet, and native Blazor lifecycle and dispatch mechanisms. No Domain, Application, or Infrastructure changes are required. This file is an implementation plan, not authorization to implement the later presentation shell.

Source inspection baseline: Git commit `2493219fee1576b98be8e672209d4d2e8d73a5fa`. Implementation and verification are complete. The verification record states the completed checks and explicit publishing/hosting limits. Source locations describe this baseline; symbols and paths take precedence if line numbers move.

## 1. Requirements & Constraints

### Verified starting conditions

- **OBS-001**: `AppStateManagementExtensions.AddAppState`, lines 44–52, creates a singleton `AppStateManager` using a debugger resolved from a scope that it immediately disposes. `AppStateManager.ResetAllAsync`, lines 68–125, opens another scope and clears provider-wide storage before resetting its retained state instances.
- **OBS-002**: `AppStateManagementBuilder.AddState<TState>`, lines 68–99, registers the same creation factory twice, once for the concrete service and once for `IAppState`. Scoped concrete and interface resolutions therefore create different instances. Several provider builders register only an interface while the factory resolves the concrete provider type.
- **OBS-003**: `AppState<TState>.StateId` derives from the model type. `AppStateManager.RegisterState` indexes only by that string. Independent instances of one state type overwrite each other's inventory entry, and `AppState.Dispose` does not unregister.
- **OBS-004**: `TakeSnapshot` returns the live object when `Enabled` is false. `SaveStateAsync` is a no-op. `LoadStateAsync` feeds loaded data through the normal mutation/history/save path and catches every exception. `ResetAsync` can schedule a delayed save before clearing storage.
- **OBS-005**: `UndoAsync` and `RedoAsync` call `SetCurrentState`, which pushes history and clears redo again. Bounded stacks discard the newest entry rather than the oldest entry when full.
- **OBS-006**: `LocalStorageUserContextProvider.GetUserContextId` compares a stored empty user ID with a null anonymous user ID and can replace the anonymous context on each call. Provider keys concatenate unescaped state and user strings and lack application, module, view-instance, workspace, and schema dimensions.
- **OBS-007**: `AppStateDebugger.TrackStateChange` is `async void`, retains an unbounded list of metadata with state values, and requires JS. Memory providers also require JS for logging. `AddAppState` does not register default `AppStateDebugOptions` unless `WithDebugging` is called.
- **OBS-008**: No AppState-specific tests or AppState call sites exist under the checked-in `tests/` and `examples/` C# and Razor sources at this baseline. The feature guide contains the existing consumer pattern. Preserve repository example source and builds without adding a migration dependency.

### Required behavior

- **REQ-001**: `AddAppState()` works with ordinary DI and logging, without authentication, `IJSRuntime`, `WithDebugging`, MudBlazor, or presentation-framework services. Default state persistence remains disabled through `ComponentScoped`.
- **REQ-002**: Manager, debugger, context, inventories, and mutable providers belong to the resolving DI scope. On Server that normally means a circuit or SSR request; in WASM it normally means the runtime. They never contain another scope's state. Component ownership is explicit and does not follow automatically from `ServiceLifetime.Scoped` or `AsComponentScoped()`.
- **REQ-003**: Preserve logical `StateId` and introduce a separate immutable runtime instance ID. Register each live object once by reference; independently created instances of the same type remain separately inspectable and resettable. Disposal removes only the originating instance.
- **REQ-004**: Concrete and interface resolutions of a scoped registered state refer to the same object. Provider selection resolves the configured provider and preserves DI ownership. Repeated `AddAppState()` calls do not add duplicate infrastructure services; duplicate `AddState<TState>()` declarations fail with a type-attributed configuration error.
- **REQ-005**: Provide an additive factory/lease API for independently owned component state. It uses the current runtime's dependencies without opening a new DI scope. Disposing a lease disposes only its created state and registration, never injected providers, JS, logging, or authentication services.
- **REQ-006**: Accepted transitions increment a per-instance monotonic revision and publish both existing events once. Snapshot, history, and persistence inputs are independent copies of mutable values. `Enabled(false)` disables optional history and persistence, not state mutation or notifications; it never makes snapshots alias live state.
- **REQ-007**: Undo, redo, restore, load, reset, and context reset have distinct transition semantics. History evicts its oldest entry. Undo/redo do not create ordinary history entries or erase the opposite stack. Loading never creates an undo entry or writes the loaded value back automatically.
- **REQ-008**: Explicit save awaits an immediate write of the captured current revision. Automatic saves coalesce edits without delaying accepted in-memory transitions for the debounce interval. Saves are serialized per state instance and always use the captured partition. A newer edit during a write remains eligible for a later write.
- **REQ-009**: Concurrent loads in one instance/context generation share one attempt. Caller cancellation cancels only that caller's wait. Failure permits an explicit retry. A completed load applies only if the instance, context generation, and edit revision still match the captured values. No late load overwrites a user edit.
- **REQ-010**: Reset cancels pending saves, invalidates pending loads, applies defaults, clears history, and clears only its own persisted key. It does not resave defaults automatically. Manager reset uses originating state/provider instances, never `CreateScope`, provider-wide `ClearAllAsync`, or user-context deletion. Registered live states remain tracked after reset.
- **REQ-011**: Add context-generation invalidation for explicit principal/workspace transitions. Advance the generation before asynchronous cleanup; reject old load, save-status, and subscription completions. Immediately replace old private values/history with defaults. State cannot silently save the previous user's model under a newly resolved user key.
- **REQ-012**: Built-in persisted keys distinguish application, module, logical state/view, stable instance key, principal or anonymous partition, workspace, and schema version using unambiguous encoding. Anonymous browser partition IDs remain stable across repeated calls and reloads when storage works. Persistence is opt-in and does not confer authorization.
- **REQ-013**: Optional preference storage failure or corrupt/unsupported data leaves usable in-memory state and a truthful status. Distinguish unavailable JS, missing data, corrupt data, failed I/O, and caller cancellation. Do not label skipped I/O as a successful load/save or mark an unavailable load completed.
- **REQ-014**: Add instance-bound selector subscriptions with equality comparison, optional renderer dispatch, deterministic unsubscribe, cancellation, and observed asynchronous failures. Read current state explicitly on mount; subscriptions do not replay initial values. Unchanged selected values cause no callback.
- **REQ-015**: Supply revision/context tokens and conditional application of an async result. Cancellation alone is insufficient. Reject a result captured before a newer state transition, context change, reset, or disposal, even when the producer ignores cancellation.
- **REQ-016**: Existing events remain available without a mandatory event bus or Notifier bridge. Selector subscriptions observe the owning state and do not perform network requests, infer data dependencies, manage routes, or subscribe across runtimes.
- **REQ-017**: Diagnostics expose owner-local metadata and bounded status/history. Payloads, identities, workspace values, and mutation reasons are excluded from default logs and retained diagnostic records. Detailed values require an explicit projection supplied by the host. Disabling debugging does not disable state or subscriptions.
- **REQ-018**: Preserve current source-level authoring: `AppState<TState>`, its five-argument protected constructor, `IAppState`, `IAppStateStoreProvider`, `IUserContextProvider`, existing builder calls, `StateChanged`, and `StateChangeWithMetadata`. Add optional capabilities through new types, overloads, and default interface implementations where necessary. Do not add required capabilities to the interfaces beyond the reviewed method rename.
- **REQ-019**: Validate the existing authoring pattern and a custom provider through the actual packed package. Prove no-auth/no-JS DI use, two independent Server scopes, native component disposal/dispatch, and a trimmed standalone WASM publish. Test fixture applications require no database or external identity service.
- **REQ-020**: Deliver repeatable BenchmarkDotNet measurements of execution time, managed bytes allocated per operation, and GC collections for AppState reads, snapshots, transitions, history, selector evaluation, ownership, diagnostics, and persistence coordination. Capture a pre-refactor baseline before production edits and a correctness-complete baseline before performance tuning. Separate comparable behavior from newly added safety work and features.
- **REQ-021**: Validate allocations from asynchronous workers with a separate process-wide allocation experiment that waits for owned work to finish. BenchmarkDotNet hot-path allocation results, retained heap after cleanup, browser memory, and transport/JS costs are separate measurements and must not be presented as interchangeable.
- **REQ-022**: Store benchmark source, environment metadata, raw machine-readable results, comparison rules, and observed limits. Reproducible timing/allocation regressions in equivalent workloads require correction or a recorded explanation before completion. Microbenchmarks do not establish production browser latency or render-mode performance.

### Contract decisions for this implementation

The names below are the target API for this plan. They are additions to the existing abstraction, not claims that the API exists at the inspection baseline.

- **API-001**: Register `AppStateManager`, `AppStateDebugger`, `AppStateFactory`, and built-in mutable providers as scoped services. Keep `AddState<TState>(ServiceLifetime lifetime = ServiceLifetime.Scoped)` and support Scoped and Transient. Reject Singleton at registration with `ArgumentException` because it cannot safely depend on runtime-scoped infrastructure. Record this intentional safety restriction in compatibility notes. Interface aliases use `GetRequiredService<TState>()`; Transient retains native new-per-resolution semantics.
- **API-002**: Add immutable `AppStateInstanceInfo` with `Guid InstanceId`, logical `StateId`, state service `Type`, `long Revision`, `long ContextRevision`, and `AppStatePersistenceStatus`. Keep `GetAllStates()` owner-local. Add `GetInstances()` returning a materialized metadata snapshot, and `UnregisterState(IAppState state)` removing by object reference. Preserve `RegisterState(IAppState)` and make it idempotent by reference. Framework-created base states attach an unregister callback internally. Custom `IAppState` implementations use explicit unregister or the factory lease.
- **API-003**: Add `AppStateFactory.Create<TState>(string instanceKey = null)` returning `AppStateLease<TState>` with `State`, `InstanceId`, idempotent `Dispose()`, and `DisposeAsync()`. Use `ActivatorUtilities` in the originating scope with a fresh copy of that state's registration options. Null `instanceKey` generates an ephemeral GUID key for nonpersisted instances; persisted instances require an explicit nonempty stable key. Direct DI resolution uses stable instance key `default`. Reject duplicate active persisted identities inside one manager. A released lease permits reuse of its stable key with a new runtime ID.
- **API-004**: Add `WithApplicationId(string)` to `AppStateManagementBuilder`; default `default` preserves the short setup path. Add `WithIdentity(string moduleId, string stateName, int schemaVersion = 1)` and `WithJsonTypeInfo(JsonTypeInfo)` to `AppStateBuilder`. Default module ID is `host`, default logical name is existing `StateId`, and default schema version is 1. Validate nonempty identifiers, schema version greater than zero, nonnegative debounce delay, positive enabled history capacity, configured provider resolvability, and JSON metadata matching the model type. Application IDs must be explicitly unique for apps sharing an origin.
- **API-005**: Add `AppStateContext` containing opaque `PrincipalKey` and `WorkspaceKey`. Add `AppStateManager.ChangeContext(AppStateContext context, CancellationToken cancellationToken = default)`. It is host-driven and does not implement authentication. Null principal means the existing `IUserContextProvider` supplies an anonymous or authenticated partition; normalize missing workspace to `none`. Before first persisted read, capture the provider partition. Recheck it before each new I/O dispatch; a different partition triggers invalidation and requires an explicit reload, never reuse of the previous model. Explicit host context overrides provider identity. Identical accepted context is a no-op; invalidation and reset advance `ContextRevision` even when no values differ.
- **API-006**: Use physical storage key `bdk:appstate:1:<app>:<module>:<state>:<instance>:<principal>:<workspace>:<schema>`. Encode every string dimension as UTF-8 Base64Url without padding; encode schema as invariant positive decimal. Use `anonymous:<stable-guid>` and `user:<opaque-key>` before encoding to distinguish identity kinds. Keep runtime GUIDs out of stable persisted keys. State-level persistence passes the canonical key as `stateId` and a fixed `v1` user-context argument to existing provider methods. Built-in providers recognize canonical keys and use them directly; legacy direct provider calls retain their existing two-argument key behavior.
- **API-007**: Add `WithLegacyStorageKey(string stateId, string userContextId)` for one explicitly selected old key. Only an owner-confirmed, same-partition preference registration may enable it. On canonical-key miss, read exactly that legacy key, validate the payload, write the canonical value, and remove the old key only after confirmed write success and a current-generation check. Never scan other identities or infer ownership. There is no automatic discovery of old anonymous keys. Schema changes default to a new key and defaults; feature-specific data migration beyond this one-key import is outside scope and must not claim to preserve arbitrary drafts.
- **API-008**: Preserve provider parameter shapes and constructor entry points; use the reviewed `SaveAsync`, `LoadAsync`, `ClearAsync` and `ClearAllAsync` names. Add cancellation-aware overloads with default interface bodies forwarding to old implementations. Also add `SaveAsync<T>(string stateId, string userContextId, T state, JsonTypeInfo<T> typeInfo, CancellationToken cancellationToken = default)` and the equivalent typed-metadata load overload; default bodies forward to the cancellation overloads. Built-in implementations use the supplied metadata, propagate cancellation through JS, and check cancellation around memory operations. Custom providers implementing the basic overloads remain usable after adopting the reviewed names, but cancellation cannot stop their in-flight I/O and their serializers remain their responsibility; capture keys and generation checks still apply. `ClearAllAsync()` remains an explicit provider-local maintenance API and is never called by manager reset or context transition.
- **API-009**: Add `AppStateVersion` containing runtime instance ID, edit revision, and context revision; expose `Version`, `IsCurrent(AppStateVersion)`, and `Task<bool> TryRestoreSnapshot(TState snapshot, AppStateVersion expectedVersion, string reason = null, CancellationToken cancellationToken = default)` on `AppState<TState>`. The conditional restore checks and commits atomically before awaiting observers. Add cancellation overloads for load/save/reset without removing parameterless methods or changing existing virtual override slots. Base load/reset overloads check cancellation, invoke the corresponding existing virtual method, and cancel only the caller's wait with `WaitAsync`; shared load and accepted reset cleanup use owner/generation cancellation. Base save overloads pass caller cancellation to their unshared explicit write. Default interface overloads check cancellation and await the existing methods with `WaitAsync`; old implementations may continue I/O after the caller stops waiting. Test dispatch through both interface and concrete references.
- **API-010**: Add protected virtual `CloneState(TState value)` using configured `JsonTypeInfo` or the existing JSON fallback. Always clone snapshots, accepted mutable inputs, history entries, and save payloads regardless of `Enabled`. A feature can override this method for immutable models or deliberate copying. Models containing services, components, callbacks, or cancellation sources are not supported persisted state. General JSON fallback retains current compatibility; trimmed consumers configure source-generated JSON metadata.
- **API-011**: Add `Subscribe<TSelected>(Func<TState, TSelected> selector, Func<AppStateSelectionChange<TSelected>, CancellationToken, Task> callback, IEqualityComparer<TSelected> comparer = null, Func<Func<Task>, Task> dispatch = null)` returning `AppStateSubscription : IDisposable`. Capture the initial selected value from an independent snapshot without emitting it. Default equality is `EqualityComparer<TSelected>.Default`; mutable collection selectors require a structural comparer when value equality is intended. Each change carries previous/current selected values and `AppStateVersion`. New selected values cancel obsolete callback work; dispatch defaults to direct invocation, and components pass their own `InvokeAsync`. Check subscription lifetime and version again inside the dispatched delegate. Observe callback tasks and contain/log failures. The helper cannot stop arbitrary feature code after an await; examples use `IsCurrent` or conditional restore before applying async results.
- **API-012**: Define persistence status values `NotConfigured`, `NotLoaded`, `Loading`, `Ready`, `Saving`, `Deferred`, `Failed`, and `Disposed`. Missing data and corrupt optional preferences result in usable defaults and `Ready`, with a safe corrupt-data diagnostic. Unavailable JS yields `Deferred`; do not cache a completed load. Other recoverable storage errors yield `Failed` without rolling back accepted memory state. Caller cancellation propagates `OperationCanceledException`. Manual save attempts complete or surface the provider error after updating status; automatic save tasks observe/report errors without unhandled exceptions or unbounded retry.
- **API-013**: Preserve the existing debugger constructor and `void TrackStateChange(IStateChangeMetadata)` method. Add `Task TrackStateChangeAsync(IStateChangeMetadata change, CancellationToken cancellationToken = default)` used by AppState. Make the legacy void entry synchronous and free of asynchronous JS. Default options disable logging/value capture; retain at most 100 metadata-only records by default when tracking is enabled. Add a configurable positive limit and optional explicit value projection. Existing `GetStateChanges()` returns a copied bounded list with old/new values absent unless projected. Null JS is valid. Context changes clear retained records before new private state can be exposed.
- **API-014**: Preserve legacy synchronous events and invoke each subscriber separately outside mutation locks. Log and contain observer exceptions so one observer cannot roll back a committed transition, prevent other observers, skip persistence, or turn a confirmed feature operation into a reported failure. Provide independent payload copies to observers; debugger failure is also observational. Same-reference `SetCurrentState` calls remain unsupported change detection; mutation methods use snapshot/restore or immutable replacement.
- **API-015**: Add public optional `IAppStateRuntime` in `AppState/IAppStateRuntime.cs` for manager-to-base-state integration. It exposes instance/version/status metadata, registration attachment, context invalidation, and coordinator cleanup without reflection over generic base classes. `AppState<TState>` implements it. Old custom `IAppState` implementations remain valid: the manager assigns their inventory ID, uses their existing reset method on context invalidation, and does not claim base-state revision/subscription/persistence guarantees for them. Their reset failures must leave manager context transition failed and affected custom states unavailable for reuse until an explicit successful reset.

## 3. Alternatives

- **ALT-001**: Keep the singleton manager and partition its dictionary by user ID. Rejected because retained live components/providers still cross runtime lifetimes and identity does not identify independent component instances.
- **ALT-002**: Create a new DI scope per component with `OwningComponentBase`. Rejected for the ordinary path because JS/authentication and other circuit-scoped services can resolve outside their originating context. A lease creates only the state and reuses current-runtime dependencies.
- **ALT-003**: Replace AppState with a new reducer/store framework or mandatory Notifier bus. Rejected because the existing typed state, events, and native callbacks cover the required behavior with less migration work.
- **ALT-004**: Rename/repackage AppState into a new headless shell package now. Rejected because independent state corrections do not require the shell's undecided package architecture.
- **ALT-005**: Automatically scan/import every old local-storage key. Rejected because old keys do not prove application/workspace ownership, and the anonymous-ID defect can leave several unidentifiable partitions. Exact-key import is explicit and preference-only.
- **ALT-006**: Continue using JSON cloning only when state is enabled. Rejected because disabling optional services cannot make captured inputs mutable aliases. Retain the JSON fallback but add typed metadata and an override for deliberate cloning.
- **ALT-007**: Automatically retry or flush all pending storage on unload/disposal. Rejected because disconnected JS and browser termination cannot guarantee delivery. Explicit awaited save provides a verifiable persistence boundary while the owner is active.

## 7. Risks & Assumptions

- **RISK-001**: Preserving source API signatures does not preserve accidental behavior. Singleton rejection, real explicit saves, corrected history, observer exception containment, and independent disabled snapshots are intentional changes. Document and test them instead of maintaining unsafe compatibility paths.
- **RISK-002**: Old anonymous keys can be unrecoverable because context IDs changed repeatedly. Optional preferences can reset safely; no automatic recovery or migration of business drafts is promised. Exact-key import requires established ownership.
- **RISK-003**: Cancellation does not roll back a storage write already dispatched. Captured partitions, serialized clearing, and version checks protect new-context state, but browser closure can prevent cleanup. Store no sensitive business payloads by default and state this limitation explicitly.
- **RISK-004**: Public `CurrentState` and custom state implementations can expose mutable objects. Preserve the existing API, document snapshot/restore discipline, and prove supported transitions; do not claim automatic detection or safety for arbitrary direct mutations.
- **RISK-005**: Old custom providers may ignore cancellation, persist live references, or use different storage semantics. Contract tests cover the supplied compatibility fixture; applications remain responsible for their provider implementation. The state layer passes independent payloads and never retargets their keys.
- **RISK-006**: Host-driven context changes must be wired by future identity/workspace adapters. This plan supplies the primitive and tests its guarantees, but does not implement circuit authentication capture or a cross-runtime bridge. Provider mismatch checks prevent silent cross-partition saves in the interim.
- **RISK-007**: JSON fallback, reflected activation, and reused Common packages can affect trimming. Publish and run the actual WASM fixture with configured generated JSON metadata. Fix AppState-owned failures; record unrelated dependency limitations instead of claiming broad AOT compatibility or expanding into a Common refactor.
- **RISK-008**: Async reentrancy can reorder observation even on a single Blazor synchronization context. Version checks must occur at commit and inside dispatched callbacks, with no awaits under state locks. Cancellation-only tests do not establish this guarantee.
- **RISK-009**: Correct snapshot copying, isolated event payloads, and safe ownership add work missing from the current implementation. Before/after results must describe that semantic difference. A zero-allocation broken path is not an acceptable optimization target.
- **RISK-010**: Thread-pool work, diagnostics, tiered JIT, CPU scheduling, and background apps can distort timings and allocation attribution. Separate warm microbenchmarks from async process-wide experiments and retained heap observations, preserve environment metadata, and rerun flagged comparisons. No new benchmark result is claimed at planning time.
- **ASSUMPTION-001**: Existing authored state classes continue to derive from `AppState<TState>` or implement the existing interfaces. No current repository example app needs migration at the inspection baseline; operation names follow the later review decision; external consumers are represented by compatibility/package fixtures.
- **ASSUMPTION-002**: Persisted values in this scope are optional UI preferences or explicitly selected safe view state. URL authority, draft recovery, business idempotency, authoritative permissions, and durable background work remain outside AppState.
- **ASSUMPTION-003**: Stable application/module/view/instance identity is supplied by consumers when sharing packages or persistence. Runtime instance IDs are diagnostic references, never durable keys or authorization credentials.
